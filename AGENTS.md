# AGENTS.md — rules for OpenAI Codex (and other coding agents)

Read this, then `CLAUDE.md` (the standing brief and contract), then `README.md`.
Where they disagree, `CLAUDE.md` wins.

## What this project is
A two-view explorer of the US aerospace & defense ecosystem for GSB first-years
choosing where to recruit.

- `prototype/index.html` is a 3D constellation. Question: *who else works on this problem?*
- `prototype/valuechain.html` is the value chain. Question: *where are the gaps?*

One question per view. Do not make either view answer the other's question.

## Stack and hard constraints (from CLAUDE.md)
- Plain HTML + CSS + vanilla JS. No build step, no framework, no npm, no package.json.
- All data lives in `prototype/data.js`. Never add a second copy of the data.
- Must work by double-clicking the HTML file (`file://`). No local server, no `fetch()` of local files.
- No third-party requests at runtime. `3d-force-graph@1.80.0` is vendored in `prototype/vendor/`; never load a second three.js; `valuechain.html` uses no libraries.
- Every data row needs a `source` URL. Do not invent facts about companies, funding or contracts; leave unverified edges out.
- Keep FACTS (sourced) and SCORES (`domestic` %, `risk` ratings: analyst judgement) visibly separate in the UI.
- Anti-scope: no login, database, accounts, saved state, news feed, document search, AI chat.
- Aesthetic: deep space, near-black, six colours bound to node types, no gradient heroes, emoji, card rows or drop shadows.
- If you make a real tradeoff, append a row to `docs/07-decision-log.md`.

## How to work
- One small, scoped change per PR (aim for 1-2 hours of work, a diff a person can review in minutes). Do not bundle unrelated changes.
- Start from the latest `main` on a branch named `codex/<short-topic>`. Never push to `main` or to someone else's branch.
- Before starting, list open PRs and read their changed files. Do not touch files or areas that an open PR changes; if your task needs them, stop and say so in the PR body instead. (Open PR #2, "Autopilot: ad-constellation", is a draft awaiting the owner; leave it alone.)
- Do not touch secrets, `.env`, deployment or infra config (`vercel.json`, `DEPLOY.md`), licensing or personal copy. No dependency upgrades.
- Never write passwords, tokens or account numbers anywhere, including PR text.
- No new major features unless an issue asks for them. Do not skip or delete checks to get green.

## Checks to run before opening a PR
There is no test suite and no build. Run what applies to your change:
1. `node --check prototype/data.js` and `node --check prototype/feedback.js` for any JS file you changed. For inline script in an HTML file, load the page and confirm there are no console errors.
2. If `scripts/check-data.js` exists on your base branch, run `node scripts/check-data.js` for any change that touches `prototype/data.js`. It must pass.
3. Open both `prototype/index.html` and `prototype/valuechain.html` over `file://` (headless Chromium is fine) at 1440 px and 390 px wide: no page errors, no horizontal page scroll, no third-party network requests.
4. Check `git diff --stat` shows only the files your task names.
If a check cannot be run in your environment, say so; do not claim it passed.

## Pull requests
- Open a DRAFT PR into `main`. Title: short, imperative. Reference the issue (`Closes #N`).
- Never merge, never enable auto-merge, never force-push. A person reviews and merges.
- The PR body must end with a "Verified" section: exactly which checks you ran, what you saw, and what you could not verify. Then end with:

```
---
_Generated by OpenAI Codex_
```
